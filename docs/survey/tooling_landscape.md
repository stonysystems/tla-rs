# Tooling Landscape

## Overview

This section surveys practical tools, libraries, and infrastructure that could serve as components in a future text→TLA+ pipeline. Each tool is assessed for its likely role, integration friction, and maintenance status.

## Parsers and AST Libraries

### SANY (Syntactic ANalyzer)

- **Description**: The official TLA+ parser. Java-based recursive descent parser generated by JavaCC. Does syntax checking, semantic analysis, and level-checking.
- **License**: MIT (part of TLA+ Toolbox)
- **Maintenance**: Active (maintained by the TLA+ Foundation)
- **Install friction**: Requires Java/JVM. Bundled with TLA+ Toolbox.
- **API/CLI**: CLI via `tla2tools.jar`. Can be invoked programmatically from Java.
- **CI scripting**: Yes — `java -jar tla2tools.jar -SANY ModuleName.tla`
- **Role in text→TLA+ pipeline**: **Validation gate**. Every generated TLA+ module must pass SANY. Essential for syntax + basic semantic checking.
- **Reuse**: DEMONSTRATED — standard tool, used by TLC and Apalache.

### tree-sitter-tlaplus

- **Description**: Incremental, error-tolerant TLA+ parser using tree-sitter. Generates an LR(1) parser in C with handwritten C for context-sensitive syntax.
- **License**: MIT
- **Maintenance**: Active (community-maintained, crates.io published)
- **Install friction**: LOW — bindings for Rust, Python, JavaScript, C. `cargo add tree-sitter-tlaplus` for Rust.
- **API/CLI**: Programmatic API via tree-sitter bindings. Full syntax tree query API.
- **CI scripting**: Yes — can be embedded in any CI pipeline via language bindings.
- **Role in text→TLA+ pipeline**: **Grammar enforcement** (constrained decoding), **AST manipulation** (post-processing generated specs), **syntax highlighting** in tooling.
- **Limitations**: Syntax-level only — no semantic analysis, no level-checking. Cannot replace SANY for validation.
- **Reuse**: DEMONSTRATED — used by Spectacle, VS Code extension, and other TLA+ tools.

### Spectacle

- **Description**: Web-based TLA+ interpreter written in JavaScript using tree-sitter-tlaplus as parser. Recently updated with basic safety checking via BFS.
- **License**: Open-source
- **Maintenance**: Active (recent updates as of 2025)
- **Install friction**: LOW — web-based, no installation needed.
- **API/CLI**: Web interface only.
- **Role in text→TLA+ pipeline**: **Quick interactive testing** of generated specs. Not suitable for CI.
- **Reuse**: SPECULATIVE — could be useful for demos but not production pipeline.

## Model Checkers

### TLC

- **Description**: The standard explicit-state model checker for TLA+. Enumerates all reachable states to check invariants and temporal properties.
- **License**: MIT (part of TLA+ Toolbox)
- **Maintenance**: Active (maintained by the TLA+ Foundation)
- **Install friction**: Requires Java/JVM. Bundled with TLA+ Toolbox.
- **API/CLI**: CLI via `java -jar tla2tools.jar -modelcheck ModuleName.tla` with config file.
- **CI scripting**: Yes — standard CI integration, widely used.
- **Role in text→TLA+ pipeline**: **Primary verification loop**. Check generated specs for invariant violations, deadlocks, liveness issues. Counterexample traces provide feedback for LLM repair.
- **Limitations**: State space explosion for large models. Requires finite instantiation of parameters.
- **Reuse**: DEMONSTRATED — industry standard, used at Amazon, Microsoft, Intel.

### Apalache

- **Description**: Symbolic model checker for TLA+ using SMT solving (Z3 backend). Checks inductive invariants and bounded safety.
- **License**: Apache 2.0
- **Maintenance**: Active (Informal Systems, GitHub releases through 2024)
- **Install friction**: MEDIUM — requires Java 17+. Docker image available. `brew install apalache` on macOS.
- **API/CLI**: CLI + **JSON-RPC server API** (new). JSON-RPC allows external tools to drive symbolic execution.
- **CI scripting**: Yes — CLI and Docker support.
- **Role in text→TLA+ pipeline**: **Advanced verification loop**. Symbolic checking is more efficient than TLC for some classes of specs. JSON-RPC API enables LLM agent integration (tool-augmented generation).
- **Limitations**: Type annotations required (TLA+ Snowcat type system). Not all TLA+ features supported.
- **Reuse**: DEMONSTRATED — used in production by Informal Systems, Quint backend.

## Specification Languages

### Quint

- **Description**: Modern, engineer-friendly specification language based on TLA (the logic) with TypeScript-like syntax. Type checking, IDE support, REPL.
- **License**: Apache 2.0
- **Maintenance**: Active (Informal Systems, frequent GitHub commits)
- **Install friction**: LOW — `npm install -g @informalsystems/quint`
- **API/CLI**: CLI-first. REPL for interactive exploration. Apalache backend for model checking.
- **CI scripting**: Yes — CLI-based, npm ecosystem.
- **Role in text→TLA+ pipeline**: **Alternative target**. If generating TLA+ syntax is too hard for LLMs, generating Quint (which has more regular syntax) might be easier. Quint→TLA+ compilation is available.
- **Considerations**: Quint is not TLA+ — it's a different surface syntax for the same logic. Generating Quint first, then compiling to TLA+, is a viable two-stage approach.
- **Reuse**: SPECULATIVE — no published NL→Quint system, but the simpler syntax may reduce generation errors.

## Benchmark Corpora

### tlaplus/Examples

- **Description**: Official collection of TLA+ specifications covering applications in a variety of fields (distributed systems, protocols, algorithms, puzzles).
- **License**: MIT
- **Maintenance**: Active (community contributions)
- **Content**: 100+ specifications with TLC/Apalache/TLAPS verification annotations.
- **Role in text→TLA+ pipeline**: **Few-shot retrieval corpus** (RAG), **evaluation reference specs**, **training data** for fine-tuning.
- **Reuse**: DEMONSTRATED — standard reference corpus for TLA+ tooling development and testing.

### TLAiBench

- **Description**: Benchmark suite for evaluating LLMs on TLA+ formal specification tasks. Logic puzzles + real-world scenarios.
- **License**: Open-source (TLA+ Foundation / community)
- **Maintenance**: Active (2025, connected to TLAi+ Challenge)
- **Content**: Standardized tasks with evaluation criteria.
- **Role in text→TLA+ pipeline**: **Evaluation benchmark**. Directly usable for measuring text→TLA+ system quality.
- **Reuse**: DEMONSTRATED — purpose-built for AI evaluation on TLA+.

### SysMoBench Artifacts

- **Description**: Benchmark artifacts for AI system modeling (11 real-world system artifacts including etcd Raft, Redis, ZooKeeper, Asterinas).
- **License**: Open (arXiv paper + data)
- **Role in text→TLA+ pipeline**: **Evaluation benchmark** for system-level specification generation.
- **Reuse**: DEMONSTRATED — automated evaluation metrics included.

### tlaplus/CommunityModules

- **Description**: Community-contributed TLA+ operators, snippets, and modules.
- **License**: MIT
- **Role in text→TLA+ pipeline**: **Retrieval corpus** for reusable TLA+ patterns and operators.
- **Reuse**: DEMONSTRATED — active community contributions.

## LLM Infrastructure

### Grammar-Constrained Decoding Tools

- **llama.cpp GBNF**: Context-free grammar constraints for token-level enforcement during LLM decoding. Already demonstrated for TLA+ syntax in TLAi Challenge.
- **Guidance framework**: Context-sensitive grammar constraints. Can enforce more complex structural properties beyond CFG.
- **tree-sitter for GCD**: tree-sitter-tlaplus grammar can be adapted as a GCD grammar for TLA+ syntax enforcement.
- **Reuse**: SPECULATIVE for TLA+-specific application (only demonstrated in TLAi Challenge entry).

### Apalache JSON-RPC API

- **Description**: New server API allowing external tools to drive Apalache's symbolic execution. Enables tool-augmented LLM agents.
- **Role**: Enables LLM agents to invoke model checking as a tool call during generation/repair loops.
- **Reuse**: SPECULATIVE — API is new, no published LLM integration yet.
