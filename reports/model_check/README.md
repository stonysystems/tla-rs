# Source-First Model-Check Artifacts

This directory stores JSON artifacts generated by:

```bash
./scripts/run_model_check_matrix.sh
```

The script rewrites the matrix artifacts and `MANIFEST.txt` on each run.

## Structural drift guard (Phase 37.2.1.j)

These artifacts are regenerated by `./scripts/run_model_check_matrix.sh` and
guarded by `./scripts/check_model_check_drift.py`, which CI runs immediately
after regeneration.

The guard compares the regenerated artifacts against the committed ones **after
normalization**: wall-clock keys (`elapsed_ms`, the `timing` subtree, the
per-phase `*_ms` counters) and `MANIFEST.txt`'s `git_rev:` line are dropped,
because they differ per host and per commit by construction. Everything else —
state counts, transition counts, telemetry fields, `spec`/`types` paths, stop
reasons — is compared exactly.

So: if you change the model checker in a way that changes its output, the
guard fails and you commit the regenerated artifacts along with the change.
It cannot go red from timing noise, which is why a raw `git diff` was rejected
(TODO 37.2.1.f) and why the artifacts were free to rot for months until
37.2.1.i found them contradicting themselves.

`scripts/check_model_check_drift.py --list-volatile` prints exactly what is
ignored. Note `timeout_ms` is deliberately **not** ignored despite the suffix:
it is a configuration input, so a change to it is real drift.
